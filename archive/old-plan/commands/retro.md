Run the sprint retro (RDS_MODEL.md sections 11 and 15).

1. Compute the metrics from the tracker files and git: throughput by type, cycle time, estimate error, review rounds, first-pass approval, escaped defects, incidents and MTTR, review catch rate, build ratio.
2. Compare with the previous sprint and the stage targets in CLAUDE.md (weekly velocity check rules apply).
3. Ask me: what went well, what went badly, one thing to change. One question at a time.
4. Propose the next sprint (6–10 tickets, mix from section 15) from TICKET_CATALOG.md. Check COVERAGE_MAP.md rows for the current project and stage: list the rows not yet covered and make sure the plan covers them before the project ends. Create the milestone and tickets after I commit to a subset.
5. Check promotion readiness (section 10) and say what evidence is missing, if any.
6. Update PROGRESS.md (LOG format) with a one-line sprint summary in HISTORY.
